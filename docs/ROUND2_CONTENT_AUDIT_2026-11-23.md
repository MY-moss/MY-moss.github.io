# 上岸模拟器 · 第二轮全事件审查与内容升级

开发基线：`development/first-round-20261123`，SHA `11c177a398ed7bb8f8e2bdd323bd0d096075395d`。本轮目标是提高现有事件的信噪比、修复伪分支、补全真实的长期故事，而非堆积内容。此报告对应未发布的开发分支。

## 一、审查方法与覆盖边界

对当前游戏静态装配链（`index.html` → 全部数据脚本 → `GameData.events`）中的每一个实际事件进行一次机器可重复的结构审计；检查 ID 唯一性、标题与描述、选择数、选择效果、完全相同的效果签名、完全重复的选择集合、缺失的效果键、条件字段、年龄窗、声明的 flag 来源及事件文件路径。

审计后生成了 `docs/EVENT_CONTENT_AUDIT_ROUND2.csv`，包含**每个最终保留事件的独立一行**，分别列出状态、文件、年龄/场景门槛及复审提示。该目录是全量结构审核，不宣称逐条完成了文学层面的人工通读；对筛出的重点文本和可能存在的高风险分支作了定向人工检查与实际修改。

## 二、新剧情：团队与家人（共 8 个新节点）

### 交接本上的空格（5 节点，两条两年+五年线）

- 入口 `arc_team_1`：综合科的新人许砚连续值班，玩家选择主动分担，或保住单位进度将调休推后。
- `arc_team_shared_2` / `arc_team_deferred_2`：两年后分别出现专项锻炼机会及积欠调休记录，玩家可真正改变协作机会、科室权责、口碑和压力。
- `arc_team_shared_3` / `arc_team_deferred_3`：再过三年，许砚的职业路径与对玩家的信任发生反馈；相关结果进入年鉴。
- 许砚属于现有 `contacts` 的稳定联系人，关系与信任按事件选择变化，不引入并行 NPC 框架。

### 冰箱上的蓝色便签（3 节点，两年后两种重逢）

- `arc_family_1`：已婚且在适龄窗口内，工作汇报与伴侣复诊时间相撞。
- `arc_family_present_2`：当年选择陪伴后，讨论如何持续守住家庭与事业的边界。
- `arc_family_absent_2`：当年选择工作后，面对多年失约的累积影响及修复成本。

两线均只添加非破坏性的 `player.flags`/`careerLog`/`contacts` 字段；旧档 `migrateState` 为新增 flag 补全 `_since`，通过既有刚性后续链确保叙事节点不会被普通随机池提前抽走。正在发生的其它关键抉择与政策项目不会被强行覆盖，导致有时需要等待一个空闲年度槽。

## 三、实测和统计

环境：Node.js 24.21.0、Google Chrome headless、Playwright、本地 HTTP 静态服务。测试命令：

```bash
node --test tests/game-smoke.test.mjs tests/round1-engine.test.mjs tests/round2-content.test.mjs
node tests/round1-simulation.cjs
node tests/round2-simulation.cjs
node tests/event-content-audit.cjs --write-catalog
# 本地启动静态服务，再运行（须安装 playwright 与 Chrome）
node tests/round2-browser.cjs
node tests/round1-exam-browser.cjs
```

- **18/18** 个静态与引擎测试通过，零失败：覆盖 20 个删除事件不再可抽取、保留关键剧情 ID、所有选择均非空且效果独特、两条新人物支线全部分支的状态与读档、 `result` 写回年鉴、家庭结构化门槛及拒贿后续。
- **浏览器测试**：1440×900、390×844、360×740 的深色模式下能启动、游玩、渲染人物持续故事、读档与显示选项反馈，零运行时 pageerror、零 4xx 资源、零页面级横向溢出；390×844 断网后仍能通过 `shangan-pages-6` Service Worker 正常加载。
- **考试流程**：真实浏览器交互三道笔试、三道面试，顺利上岸并进入职业阶段；无页面错误。

### 400 个固定种子（共 5,200 个职业年度）

模拟从 24 岁、工龄 1 年开始，每局最多 13 年，其中 200 局预设已婚；四种性格、三种政治面貌、不同单位轮换，选项采用种子驱动的随机策略。
